What is a "Session" in this system?

Everything else — correlation, timelines, T1/T2 handoff — depends on this answer. Pick the model that best matches how you think about a user's "unit of work".

A

Feature Invocation

A session is one user action (button click, shortcut) and all the underlying log events it triggered — WebSocket calls, plugin responses, errors. Duration: milliseconds to a few seconds.

Best for: debugging "why did this click fail?" or tracing one feature end-to-end.

B

iRacing Race Session

A session maps to an iRacing subsession_id — everything that happened from session_start to session_end. Duration: minutes to hours.

Best for: "what happened during this race?" — incidents, actions, errors across the full session.

C

Claude Code Session

A session maps to one Claude Code conversation (session_id from the hook). Contains all tool calls, token usage, lifecycle events for that AI work session.

Best for: "what did the AI assistant do this session?" — cost, tools used, errors, agent behavior.

D

All of the above — nested hierarchy

Sessions are hierarchical: a Work Session (user sitting down) contains one or more iRacing Sessions, each containing many Feature Invocations. Claude sessions run in parallel and are linked by time.

Most powerful for correlation, but more complex to build. This is the full "story" model.
